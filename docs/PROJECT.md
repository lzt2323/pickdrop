# 拾传 · PickDrop 项目说明

> 本文定义项目目标、功能范围和架构边界，供开发与产品决策参考。整理日期：2026-10-16。当前源码版本：`0.6.0-alpha.6`，处于 Tauri 迁移预览阶段。
>
> 本文定义项目目标与架构边界；当前进度、实际验证和未完成事项见 [STATUS.md](STATUS.md)，历史迁移与回退见 [迁移记录](tauri-migration.md)。

## 1. 项目概述

**项目名称：** 拾传（PickDrop）。

**项目简介：** 以群聊方式在局域网设备之间交换文字和文件的跨平台工具。用户将电脑和手机加入同一个群组，即可发送内容、查看本地历史并保存收到的文件。

**项目定位：** 面向个人多设备及可信局域网内的小范围协作，提供轻量、直接、可持续使用的文件收件箱。当前主线采用 Tauri 2 客户端与 Rust 同步核心，安装后的应用不依赖 Node.js 或开发服务器。

## 2. 项目目标

### 核心目标

- 降低跨设备传输成本：让文字、图片和文件能够通过熟悉的聊天操作发送到指定群组。
- 保持操作可控：明确发送目标、入群审批、传输状态和失败原因，避免误发与静默失败。
- 保留使用连续性：本地保存设备身份、群组与历史，重启后能够恢复，并提供连接异常时的恢复入口。
- 统一跨端能力：桌面与手机共享协议和核心业务规则，通过原生宿主适配各平台的文件与窗口能力。
- 保持轻量和可维护：减少空同步、历史处理和界面更新的无效工作，以实际测量决定性能优化。

### 预期效果

用户可以在电脑与手机之间快速传递内容，无需为每次传输重新建立群组；接收结果可以查看、保存或分享。桌面端能够作为随手可用的小窗口，手机端适配全屏操作。

## 3. 核心功能

以下为当前源码中的主要能力；平台验收程度见第 6 节，不将源码存在等同于所有平台可用。

| 模块 | 功能目标 | 当前实现范围 |
| --- | --- | --- |
| 设备与群组 | 管理设备身份和不同传输场景 | 本地身份、设备改名、群组创建与切换、退出群组、成员管理与移除 |
| 邀请与审批 | 控制设备加入 | 邀请地址、邀请码、二维码与移动端扫码入口、申请及成员审批 |
| 发现与连接 | 找到并连接同群设备 | mDNS、Android 系统 NSD、已验证地址保存、同群设备手动地址连接 |
| 文字与历史 | 交换简短内容并回看 | 双向消息同步、本地历史、分页读取、重启恢复 |
| 文件传输 | 可控地发送和接收文件 | 文件选择、拖入与桌面剪贴板图片粘贴、待发草稿、明确发送、进度、取消、大小与 SHA-256 校验 |
| 文件使用 | 将收到的内容交给系统应用 | 打开、另存为、分享、图片缩略图，以及移动端相册导出适配 |
| 桌面窗口 | 降低频繁传输时的操作成本 | 固定、隐藏与恢复、多窗口、贴边收起与展开、托盘退出 |
| 手机交互 | 接入系统文件与分享流程 | 全屏布局、原生文件提供商、Android 外部分享接收、确认后发送 |
| 存储管理 | 查看和清理本地缓存 | 核心消息与文件缓存统计、清理入口；原生选择草稿和系统导出暂存另行管理 |

### 必须保持的交互规则

- 选择、拖入、粘贴剪贴板图片或从系统分享接收文件后，先进入待发状态，由用户确认发送。
- 入群申请由 Rust 核心保存并继续确认审批；关闭等待面板只结束当前界面等待，申请设备重启后可恢复未完成的入群。
- 发送过程中切换群组，不改变已经确定的发送目标。
- 传输失败、取消与成员权限变化应有明确状态，不能显示为成功。
- 文件完成校验后才作为已接收文件交给用户打开或导出。
- 文件拖到收缩后的动物图标时，松手前保持拖放目标可见；松手后展开群聊并进入待发送附件。
- 桌面长驻开启时保持展开并置顶，优先于自动贴边与手动收缩；关闭长驻后沿用原贴边设置。
- 桌面关闭窗口与退出应用分开处理：关闭隐藏窗口，托盘退出结束应用。

## 4. 范围与非目标

### 当前范围

- 可信、设备间可互通的局域网。
- 仅开发 Tauri 桌面与移动端共享客户端及 Rust 核心；Node Linux TUI 已退役，没有 Rust TUI 替代。
- 兼容现有 `pickdrop-peer-v1` 签名协议。
- 保留显式、非破坏性的旧桌面数据导入；旧运行源码通过 Git 历史回退，不留在当前工作区。

### 当前不提供或不保证

- 公网服务、云中转和云端历史备份不属于当前主线范围。
- 当前传输没有 TLS 或端到端加密；设备签名用于身份与事件验证，不代表内容加密。应用面向可信局域网，不应直接开放公网。
- 不保证离线投递、手机后台长时间在线或传输，也不保证断点续传。
- 不保证跨 AP、组播受限或网络隔离环境中的自动发现；已有同群设备可尝试手动地址连接，但仍需网络可达与签名验证。
- iOS 外部分享接收扩展尚未迁入。
- 不自动覆盖旧版数据、升级正式应用身份或发布正式版本。

新增需求应按 AGENTS.md 评估用户价值、简单替代方案、系统影响和维护成本，再决定接受、简化、推迟或拒绝。

## 5. 技术架构与目录职责

### 主线调用关系

```text
网页界面（apps/tauri/src）
  → bridge.js：core_call / 原生命令
  → Tauri 原生宿主（apps/tauri/src-tauri）
  → Rust 同步核心（crates/pickdrop-core）
  → 局域网 HTTP / mDNS / 本地持久化

核心事件 → pickdrop:event → 界面状态与传输进度更新
```

前端使用 JavaScript、CSS 与 Vite，负责展示和交互；原生宿主负责窗口、生命周期、文件选择与系统集成；Rust 核心负责身份、群组、协议、同步、文件传输与持久化。新客户端不带 Electron 或 Node sidecar。

| 路径 | 职责 |
| --- | --- |
| `apps/tauri/src/` | 主线界面、状态模型、文件草稿与原生桥接 |
| `apps/tauri/src-tauri/` | Tauri 宿主、平台适配、窗口与原生命令 |
| `crates/pickdrop-core/` | 共享 Rust 核心、协议实现及核心集成测试 |
| `apps/tauri/tests/` | 前端单元测试、浏览器及交互回归脚本 |
| `tests/` | 开发工具回归、协议兼容向量及真实 Rust 节点前端验收 |
| `scripts/`、`.github/workflows/` | 开发检查、构建、版本管理与 CI |
| `docs/`、`assets/brand/` | 当前规范、发布说明与品牌素材 |

### 模块归属与开发约束

| 模块 | 应放入的代码 | 不应承担的职责 |
| --- | --- | --- |
| `apps/tauri/src/main.js` | 页面组装、DOM 更新、交互绑定 | 文件传输生命周期、协议与文件权限实现 |
| `apps/tauri/src/file-transfers.js` | 发送批次、接收、重试、草稿并发与进度状态 | DOM 查询、直接调用 Tauri 插件 |
| `apps/tauri/src/join-request.js` | 入群轮询、请求去重、停止与失效响应处理 | DOM、原生插件与页面导航 |
| `apps/tauri/src/bridge.js` | 核心及原生命令桥接 | 复制 Rust 业务规则 |
| `crates/pickdrop-core/src/lib.rs` | Core 公共入口、共享状态与业务协调 | HTTP 路由细节、平台 UI |
| 核心 `http.rs` / `network.rs` | HTTP 边界 / 网络选址与发现校验 | 前端状态与窗口行为 |
| 核心 `pairing.rs` / `sync.rs` | 邀请、审批与入群 / 同步调度、连接与在线状态 | HTTP 传输细节、平台交互 |
| 核心 `files.rs` / `migration.rs` | 文件传输和缓存 / 显式旧数据导入 | UI 与平台文件选择器 |
| 宿主 `lib.rs` / `host.rs` | 启动注册与生命周期 / 状态与路径授权 | 页面业务与重复协议实现 |
| 宿主 `native_files.rs` / `window_commands.rs` | 系统文件操作 / 窗口命令与操作保护 | 跨入其他窗口的私有状态 |

宿主 `docking.rs` 管理贴边窗口状态、持久化与系统操作；`docking/geometry.rs` 负责尺寸、坐标、缩放和边缘判定，纯计算不依赖 Tauri。

新逻辑先归属现有领域模块；只有独立职责和实际维护需求才拆文件。不得将领域逻辑放入无明确所有者的 `utils` 或 `shared`。Rust 内部模块保持私有，仅开放必要的内部接口；外部继续通过 Core 与已注册原生命令访问。前端传输模块通过显式回调连接桥接和渲染，不能反向导入页面入口。

重构须保留命令名、参数、协议、持久化格式和用户确认发送语义。新增或变更行为需要对应回归测试；检查标准沿用 CONTRIBUTING.md 与现有 CI。模块拆分、待办和本轮验证统一更新 STATUS.md，不再为每次修改新建一套交接稿。历史发布、迁移回退、素材来源和仍适用的验收说明保留。

### 架构约束

- 核心业务规则归 Rust 核心；界面与平台适配通过明确接口调用，避免重复实现协议。
- 延续 canonical JSON、Ed25519 签名、SHA-256 事件标识与文件校验，以及成员授权和撤销规则。协议变更须通过保留的旧 JS 签名向量验证兼容性。
- 历史分页读取、界面增量更新；空同步不重复校验或重写整个历史，文件采用流式处理。
- 私钥不暴露给前端 DTO；原生文件操作限制在允许的路径范围内。
- 优先扩展现有模块，不为假设中的需求增加框架、抽象层或平行架构。

## 7. 开发与验收

开发环境使用 Node.js 24、pnpm 11，具体 pnpm 与 Rust 版本分别以 `package.json` 和 `rust-toolchain.toml` 为准。Android、iOS 与桌面原生构建还需要对应系统工具链，详见 [开发约定](../CONTRIBUTING.md)。

```sh
pnpm install --frozen-lockfile
pnpm start
```

代码变更按影响范围执行检查；完整主线检查入口为：

```sh
pnpm version:check
cargo test -p pickdrop-core --locked
cargo check -p pickdrop-tauri --locked
pnpm --dir apps/tauri test
pnpm --dir apps/tauri build
pnpm --dir apps/tauri test:browser
pnpm --dir apps/tauri test:join
pnpm tauri:test:runtime
```

验收要求：

- 协议与权限：验证签名兼容、成员授权及撤销，不能以跳过校验换取性能。
- 真实链路：使用真实节点验证入群审批、双向消息、文件哈希、重启恢复；浏览器模拟桥接不能替代真实链路。
- 原生功能：按平台分别验证扫码、文件提供商、分享、相册、窗口、前后台和网络变化。编译成功不能替代真机验收。
- 性能：核查空同步工作量、历史分页、消息节点复用和大文件处理；测试计数不能替代实际帧率或内存测量。
- 文档与交付：记录执行的检查、结果和未覆盖项；功能或架构边界变化时更新本文，阶段进度另行维护。

版本、锁文件、发布与回退遵循 CONTRIBUTING.md。稳定发布前须完成相应验证；迁移和日常开发不自动合并、创建发布标签或覆盖旧资产。

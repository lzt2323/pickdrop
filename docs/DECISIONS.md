# 工程决策

## 2026-10-15：入群确认归 Rust 核心，独立于等待面板

审批侧已有成员记录而申请侧没有群组的现象已复现：此前唯一的 check_join 轮询绑定等待面板，关闭面板后不再接收批准快照。选择在现有 pairing 模块保存待确认申请并周期处理；相比在每个页面或 localStorage 中维持后台任务，核心统一负责协议、持久化和跨端恢复，不新增框架或依赖。新文件 pending-joins.json 为附加本地状态，不修改现有身份、群组或签名协议格式；旧版已丢失的申请凭据不能补回，需要重新申请。

入群任务与已有同步周期分开，避免一个不可达邀请地址阻塞在线群组。申请设备活动时重试，重启后恢复；拒绝、过期和撤销清理待确认状态，错误记录到宿主日志。重复批准结果合并已验证事件，保留新消息、后续权限和当前群组选择。关闭界面仍禁止迟到结果强制导航。审批主机重启导致内存票据失效的限制继续明确记录，本轮不扩展到完整邀请服务持久化。

用户明确要求轻量 Rust TUI，并授权在指定 Linux 服务器测试。本决定扩展此前仅 Rust/Tauri 的产品范围：新增 crates/pickdrop-tui，终端适配与协议/同步保持分离；不恢复旧 Node 运行代码。旧 TUI 仅通过 Git 历史参考命令、审批及发送确认语义，参考后不复制到工作区，不改写历史。

文件草稿按群保存，确认后发送；失败与取消保留草稿，接收导出使用 create_new 拒绝覆盖已有目标。数据目录使用独占文件锁，防止两个终端进程同时写同一身份。核心新增显式 IPv4 绑定入口，TUI 默认回环监听，服务器测试不开放公网端口；既有 Tauri 调用仍沿用原行为。Linux x64 构建、终端/双节点验收和独立二进制归档接入 CI，实际发布继续需授权。

## 2026-10-16：通用 Linux 联网配置与本机数据清理

用户选择首次启动自动绑定私有局域网 IPv4；没有合适物理网卡时仅回环，公网需要明确选择。默认不再要求每台 Linux 手改启动脚本，也不采用默认 0.0.0.0 暴露全部网卡。复用核心已有网卡排序/虚拟接口排除规则，增加只读接口供 TUI 列出 IPv4 和选择私有地址；不为 TUI 复制网络探测实现。自动选择在启动时执行，改设置需重启，命令行 --bind 优先并有提示。实际服务器已获授权的公网地址迁入其本机设置，不写入通用源码或启动器。

用户选择清缓存和本机群聊数据、保留身份与设置。因此提供两个明确入口：缓存清理保留聊天；群聊清理移除本地群组关联、历史、待入群申请、草稿及缓存，保留身份/名称/偏好，不发送解散或全局删除。签名历史不能随意裁剪后继续充当完整副本，清理后需邀请重新加入，历史可能再次同步；没有增加同步协议中的全局删除功能。

清理默认取消，群聊清理还要输入确认文字。退出核心并丢弃 Tokio 运行时、等待任务结束后才执行本地文件清理；数据目录独占锁始终保留，防止迟到同步写回或其他进程抢占。仅按应用文件归属删除，不递归删除整个 data 或外部保存目录；失败明确报错。清理验证仅对生成数据执行，不清用户真实服务器数据。

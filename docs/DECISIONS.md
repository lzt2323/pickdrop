## 2026-10-15：按维护状态治理仓库

用户已要求解决仓库目录、历史文档、新旧命令和结构约束混乱。本次接受该治理范围，保持现有运行架构和公开接口。

- 当前开发入口集中于 PROJECT、STATUS、本文及文档导航；历史 UI 原型和评审整体迁往 `docs/archive/`，连同素材和生成脚本保留相对引用。
- 旧客户端指南迁往 `docs/legacy/`；旧版专题实测记录进入 `docs/archive/legacy/`。`plans/` 的残余评分数据迁入对应历史 UI 评审目录，不再保留无任务职责的目录。
- 源码按已有包边界保留。把所有旧代码搬进 `legacy/` 会同时影响 TUI、JS/Rust 协议交叉测试、打包清单和移动原生工具，收益不足以承担本次额外风险。通过目录所有权说明与明确命令区分维护状态。
- 旧客户端命令统一提供 `legacy:` 入口；已有命令保留别名，避免破坏开发者脚本。根检查覆盖主线前端与原有 Node 检查，CI 独立运行结构约束。
- 自动约束覆盖非忽略文件的根目录归属、文档分区、维护文档本地链接、前端字面量依赖边界和循环。计算导入、完整 Rust 依赖关系及运行时行为仍由代码审查、编译和回归验证，不将静态检查称为完整架构证明。

相比只增加说明，本次实际迁移资料、修复链接并增加自动失败条件；相比全仓路径重写，保留现有运行包路径和协议降低兼容风险。不新增框架或依赖，不改用户数据，不合并或发布。

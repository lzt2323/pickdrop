# 自动贴边与文字输入研究

研究日期：2026-10-13。范围：桌面 mini 窗口的贴边、收起、展开与缩放，以及 Android 消息选择、复制和输入。以下将官方产品行为与拾传的设计选择分开记录。

## 官方依据

- [Dropover · Pro Tips，Tip #12](https://dropoverapp.com/tips)：支持把文件架拖到屏幕边缘停靠，停靠后保留在边缘，按需恢复。它说明了「自然拖动进入停靠」这一交互；该页面没有给出自动收起的延时数值。
- [Unclutter · Features](https://unclutterapp.com/features)：默认把指针移到屏幕顶部并向下滚动打开；面板可通过标题栏拖动，尺寸调整有固定把手。这说明边缘工具应有明确的唤回位置，并把移动和缩放分成可预测的操作。它不是鼠标一离开就收起的实现证据。
- [Android · TextView](https://developer.android.com/reference/android/widget/TextView#setTextIsSelectable(boolean))：建议有用的非编辑文字允许选择和复制；编辑框本身可以选择文字。拾传用 WebView 的可选择文字实现同一交互原则，不调用此原生 TextView API。
- [Android · Copy and paste](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste)：Android 13 起系统提供复制反馈，并建议避免重复 toast。输入后的粘贴由系统编辑菜单承担。

本轮借鉴的是以上产品的交互原则。没有将其他产品的截图、内部算法或收起时间冒充为已验证事实。

## 拾传的行为选择

桌面窗口拖到当前显示器工作区左、右、顶部或底部附近后进入停靠状态。拖动期间指针控制位置，窗口不因检测到边缘而重新摆放。用户仍在面板内操作、打开弹层、进行文件拖放或主动上传时保持展开；离开面板后给予 800 毫秒缓冲，再收起成可见的小动物。缓冲值属于拾传自己的实现选择；同一窗口的连续事件合并到一个等待任务，避免拖动期间重复创建大量任务。

停靠的面板仅在收起时显示独立动物；展开时隐藏独立动物，避免窗口内群组头像与顶部动物叠加。悬停或点击动物恢复面板。拖动动物应改变恢复位置，避免拖动中展开。恢复与缩放依据面板自己的保存范围计算，左边保持左边、右边保持右边、顶部保持顶部、底部保持底部；不再为动物额外留出 56 + 8 逻辑像素。

自由浮动的窗口不因失焦而自动消失。置顶只控制层级，不与停靠收起混为同一个开关。该选择符合用户本轮「拖到边缘且不使用时自动收缩」的要求。

手机消息不常驻复制图标，也不把双击文字绑定到整条复制。长按文字通过 WebView 的系统选择菜单选择和复制；长按输入框通过编辑菜单粘贴。输入框保持可点击、可编辑，默认无占位短句、无预填测试文字。用户自行输入而保存的草稿应继续保留，不通过清空应用数据来伪造空白初始状态。

## 初始代码审查

旧实现的 `expand` 在贴边状态同时显示独立动物，且把动物的可见坐标反推到主窗口，再为动物加入间距。`moved` 检测到边缘后立即异步调用 `expand`，这使自然拖动和部分缩放产生的位置事件触发第二次移动。这是顶部双动物与窗口偏移的直接代码路径。

旧实现手机端复制按钮通过 `@media(hover:none)` 强制显示，造成每条消息旁都有常驻复制标记；同时双击消息被绑定为复制整条，与系统选择操作存在冲突。输入框是实际 textarea，原有占位短句造成类似预填文本的观感；应移除占位并保留无障碍标签。

## 边界与验收

| 情况 | 预期 |
| --- | --- |
| 拖到左、右、顶部、底部，指针仍在面板内 | 保持面板，位置不二次跳动 |
| 停靠后离开面板 | 延迟收起；动物可见，主面板隐藏 |
| 悬停或点击动物 | 面板恢复，独立动物隐藏 |
| 设置、确认框、文件拖放、上传 | 不因失焦或鼠标短暂离开而打断 |
| 面板自由浮动后切到其他应用 | 仍保持原窗口 |
| 四边停靠后连续缩放 | 相应屏幕边缘保持稳定，不叠加动物间距 |
| 1、1.5、2 倍显示缩放和负坐标显示器 | 逻辑尺寸只换算一次，恢复目标和面板均位于工作区 |
| Android 长按收到或自己发送的文字 | 允许选择和系统复制，不出现常驻复制按钮 |
| Android 长按空白输入框 | 可以粘贴；输入、换行、输入法合成均可操作 |
| 空输入和文件草稿 | 默认空白；空内容不能发送，选文件可发送 |

自动化 DOM/CSS 检查不能证明 Android 选择菜单正常，也不能证明真实 macOS 拖动不跳动。两者应分别以模拟器长按/粘贴和原生窗口几何证据验收。多屏跨 DPI 移动还需区分「函数尺度回归通过」与「真实多屏操作通过」。

## 实现复审提示

原生 `apply` 同时设位置与大小时，系统窗口回调可能异步且顺序不固定；必须屏蔽由自身布局产生的事件，避免覆盖保存范围。边缘检测采用工作区，不能把菜单栏或 Dock 覆盖区域当可用面板区域。恢复不能只隐藏旧面板而没有成功创建可见恢复目标；创建失败应保留原窗口。

长按与浏览器内默认选择依赖实际 WebView；`user-select: text` 是必要配置但不是实机验收。不得在文字气泡上使用取消默认行为的触摸处理。去掉占位以后，应保留 textarea 的关联标签、足够高度与对焦反馈，帮助用户找到输入位置。

## 本轮前端独立复审

直接查看 `artifacts/ui-review/auto-edge` 中桌面聊天、手机聊天、手机短标题空闲、窄屏聊天四张截图：群组标题和下箭头对齐，桌面不再有手动收起按钮；手机消息没有常驻复制图标，默认空白输入区仍有轮廓和两侧文件／发送按钮。未发现阻断本轮目标的 P1 视觉问题。

窄屏截图暴露一个 P2：缩略图载入时的图像占位符 SVG 未指定大小，以浏览器默认大尺寸渲染后被裁切，影响观感。建议将加载／失败状态图标约束到 24 像素，并补充延迟缩略图场景检查。该反馈已交给主程序员。

主任务已验证浏览器通过实际 Meta+V 命令粘贴文字。Android WebView 长按、真实桌面四边停靠和连续缩放尚待设备验收；本节不将图库或浏览器检查表述为设备已通过。

# 拾传当前代码评审与贴边交互方案

评审对象为 2026 年 10 月 13 日工作区的 Tauri 0.6.0-alpha.1，包括未提交改动。发现 5 个可复现问题，首先应修复动物入口文件被广播到其他群窗口的错误。贴边体验需要明确区分临时预览、主动操作和拖入文件，单独调整圆角或延迟无法解决这些问题。

## 需要修复的问题

### P1 动物入口拖入文件会发送到其他群窗口

位置：[lib.rs:604](../../../apps/tauri/src-tauri/src/lib.rs:604)、[main.js:725](../../../apps/tauri/src/main.js:725)。

`owner.emit("pickdrop:anchor-drop", paths)` 会广播到所有监听窗口。每个窗口的处理器随后以自己的 `app.groupId` 调用 `sendFiles`，没有核对 owner，也没有目标群的事件快照。打开群 A、群 B 两个窗口后，向 A 的动物入口拖入一份文件，两个窗口会分别向 A 和 B 发送。文件路径授权也在共享 Host 中，不能阻止 B 读取这份文件。

隔离复现执行了两个真实浏览器 renderer 的生产处理器，得到 `send_file(groupId=g1)` 和 `send_file(groupId=g2)` 两次调用。广播语义已核对本机安装的 Tauri 2.12.3 源码，并与 [Tauri Emitter 文档](https://docs.rs/tauri/2.12.3/tauri/trait.Emitter.html) 一致；没有在用户实际群组发送测试文件。

修复：使用 `emit_to` 定向投递；前端监听同时限定当前窗口 target。事件应包含 owner label、固定的 groupId 和 dropId，接收端校验归属并去重。清除忙碌状态必须等待该 owner 的处理完成，避免其他窗口的 finally 提前清除保护。

### P1 发送中新增附件被整批清除

位置：[main.js:581](../../../apps/tauri/src/main.js:581)、[main.js:588](../../../apps/tauri/src/main.js:588)、[main.js:600](../../../apps/tauri/src/main.js:600)。

发送 A 文件等待完成期间，「选择文件」仍能添加 B。发送函数持有旧的 A 数组，附件选择则用新数组保存 A+B；A 完成后，提交处理器直接删除整个群的附件草稿，B 从界面和持久化数据消失，却从未发送。隔离复现确认只有 `/review/first.txt` 被发送，新增的 `/review/second.txt` 消失。

修复：为每份草稿创建稳定 ID；发送时复制本批次快照，结束后只删除成功的快照条目，合并失败项并保留期间新增的条目。待发送列表的移除操作也应作用于草稿 ID，不能修改正在遍历的发送数组。

### P1 拖入文件绕过发送确认

位置：[main.js:725](../../../apps/tauri/src/main.js:725)、[main.js:731](../../../apps/tauri/src/main.js:731)。

主窗口和动物入口的原生 Drop 都直接调用 `sendFiles`。这与项目 README 的「拖入文件后保留为待发草稿，点击发送才传送」不一致，也与文件选择器流程不同。用户无法在发送前核对当前群、移除文件或取消整批发送。隔离复现中，仅投递原生 drag-drop 事件即出现一次 send_file，草稿数量为 0。

修复：三种入口共用“加入草稿”流程，固定拖入时的目标群并显示文件数，用户点击发送后再传输。如未来支持拖入即发，应做成明确的可选偏好，并显示目标群。

### P2 窗口状态和动物图标会跨窗口污染

位置：[docking.rs:145](../../../apps/tauri/src-tauri/src/docking.rs:145)、[docking.rs:322](../../../apps/tauri/src-tauri/src/docking.rs:322)、[bridge.js:35](../../../apps/tauri/src/bridge.js:35)。

`pickdrop:window` 通过主窗和 anchor 两次全局 emit 发出；`pickdrop:animal` 同样使用全局 emit。一个窗口贴到左侧、收起或置顶，其他窗口 UI 也会更新到同一 edge/pinned/collapsed。例如右侧窗口会误用左侧的缩放方向，置顶按钮状态与其真实窗口层级不一致；切换群的动物更新也会改掉其他群的入口图标。

隔离复现中，向左侧窗口发出的状态使两个 renderer 都显示 `edge=left` 和 `aria-pressed=true`。修复与文件投递一致：窗口局部事件全部限定目标，同时把 owner label 放入 payload 供接收端验证。Core 群组与消息更新仍可广播。

### P2 动物入口 Drop 后拖入保护没有释放

位置：[anchor.js:14](../../../apps/tauri/src/anchor.js:14)、[docking.rs:635](../../../apps/tauri/src-tauri/src/docking.rs:635)。

Enter 设置 `file-hover=true`，只有 Leave 清零；Drop 只修改高亮。成功放下文件的事件序列通常是 Enter→Over→Drop，不会再触发拖出时的 Leave。本机 Wry 0.57.0 macOS 实现也分别发送 Drop 和 Leave，没有在 Drop 后补 Leave。

因此 upload-busy 虽在 finally 清除，file_hover 仍为 true，`can_collapse` 持续拒绝自动收起。隔离执行原生产 anchor.js 的 Enter→Drop 序列，file-hover 的调用记录只有 `[true]`。修复：Drop、Leave、取消和异常都清除拖入保护；传输保护使用独立状态，原生端应负责配对释放，避免依赖 webview 是否收到末尾事件。

## 贴边体验还缺少的规则

当前动物入口是 56×56 的透明独立窗口；悬停 250ms 和点击都执行 expand，离开面板后以 800ms 延迟判断收起。接近任一工作区边缘 24 个逻辑像素就标记 edge，但移动时没有完成几何吸附，也没有入边与离边的不同阈值。面板会在收起后的恢复阶段才对齐边缘，容易给人“先贴着，随后跳过去”的感觉。

另有两项需要原生验收的风险：悬停和点击共用 `w.show()`，本机 Tao macOS 的 show 路径会调用 `makeKeyAndOrderFront`，不能保证预览不改变键盘窗口；主窗口文件拖入 Enter/Over 和文件选择器没有专用忙碌保护，拖入与系统弹窗期间的收起规则也不完整。这两项没有作为已实测的 macOS 焦点故障计入上述 5 条。

## 建议方案

保留动物作为群组身份，但给它明确的入口容器。提供两个可比较方向：**窄边签**减少桌面遮挡；**动物胶囊**保留完整 48px 动物。两者都显示有意义的未读、待发或失败状态，并提供群名提示。正常状态安静，不持续弹跳。

默认优先左右两侧，顶部和底部保留为可选位置。拖动中显示停靠预览，松手才吸附；进入阈值先用 24px，脱离阈值先用 40px，在真实手拖测试后调整。角落优先保留原停靠边。多窗口入口沿边排列，避免重叠；跨屏接缝和系统 Dock 占用区域需要单独验收。

| 状态 | 进入 | 展示与焦点 | 离开 |
| --- | --- | --- | --- |
| 收起入口 | 停靠后闲置或主动收起 | 边签或动物胶囊，群身份与状态可见 | 悬停、点击、拖入或恢复快捷键 |
| 临时预览 | 悬停约 300ms | 小面板显示最近文件，不激活键盘窗口 | 指针离开入口与面板联合区域约 700ms 后收起；点击转主动操作 |
| 主动操作 | 点击或键盘恢复 | 窗口进入前台，输入和键盘操作可用 | Esc 或失去焦点后按偏好收起；指针离开本身不打断输入 |
| 拖入待发 | 文件拖入并放下 | 明确目标群与文件数，加入草稿；不发送 | 发送、移除或保留草稿后收起 |
| 操作保护 | 系统文件对话框、应用弹层、原生拖出 | 暂停收起，按原因计数 | 最后一个操作结束后重新判断收起 |

“置顶”继续只控制窗口层级。“自动收起”成为独立偏好。快捷键、右键菜单和可见控制提供恢复与收起替代路径。

## 修复顺序和验收

1. 定向投递窗口局部事件，覆盖两个不同群和两个相同群窗口，确保一次拖入只创建一次草稿。
2. 三种文件入口统一加入草稿；批次用稳定 ID 与快照，覆盖发送中新增、移除、切群、失败和重试。
3. 完整释放拖入/系统弹窗忙碌状态，再实现预览与主动操作的焦点分离。
4. 接入停靠预览、松手吸附、阈值迟滞、边缘入口排布；最后打磨展开收起动画。

本轮前端 5 个模型单测、Tauri 13 个库测试、Core 24 个测试以及 Vite 构建通过。新增隔离脚本确认上述 5 个问题，并确认普通成功发送后的附件草稿在刷新后保持清空。测试使用 headless Chromium 和 mock Core/native APIs；原生事件广播和 macOS Drop 语义依据当前安装依赖源码核对。没有执行实际 OS 手拖、多屏、Windows、Android 或焦点交接验收。

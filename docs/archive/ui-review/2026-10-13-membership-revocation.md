# 成员移除同步与本地移除回归

Android 完整交互测试在真实申请、批准、加入后复现：群主移除手机成员后，手机等待 15 秒及主动重连仍可编辑发送，未出现撤销提示。问题在 Rust 同步协议而非 UI 样式。

## 根因与修复

- 原同步服务对已经被移除的请求设备调用 `merge_authorized(..., false)`，导致请求在返回撤销信息前被拒绝；原响应对非成员也不返回事件，客户端无法得知自己已被移除。
- 不把 `revoked` 布尔值当成成员权限依据。新可选 `revocations` 字段仅传递针对该设备的群创建者签名 `member.remove` 事件。验证群 ID、目标 ID、创建者 ID/公钥、签名、事件摘要和结构后，客户端保存有限撤销凭证，推送 `membershipRevoked` 状态。
- 未获授权设备不返回普通事件、已知历史 ID、其他设备路由或事件接受清单；凭证的父引用只包含摘要，不披露父事件内容。只有曾获准加入的相同设备 ID 与公钥可以取得自己的撤销凭证。
- 凭证不代替正常事件图验证历史作者权限。收到完整且合法的事件图后删除已吸收凭证；创建者重新批准加入仍可生效，旧移除凭证重放不会覆盖合法重新加入。
- 维持未知新成员携带其他成员合法批准事件向第三节点同步的原行为。无权限批次仍完整回滚，不能以旧身份发送消息或恢复自己。
- 已验证退出、解散或被移除的群可移除本地记录；正常活跃成员仍必须先退出。

## 验证

`crates/pickdrop-core/tests/revocation.rs` 四项通过：

1. 两个真实 Rust 节点：离线成员错过私人文本与文件后被群主移除，只收到自己的签名撤销凭证；发送、邀请、下载及伪装公钥访问均拒绝；客户端收到状态事件，重启后仍撤销，本地移除成功。
2. 伪造签名、错误群和错误目标拒绝且状态不变；禁止自行恢复；合法完整事件图重新批准加入后，旧凭证重放不再次撤销。
3. 活跃成员直接移除记录拒绝，已退出和已签名解散状态可移除。
4. 三节点：由其他成员批准的新设备可向尚未知道该设备的原节点转发已签名批准事件，继续成功同步。

修改后既有 Core 协议、网络、文件、取消、迁移与生命周期测试均通过；`ui_bridge` 已重新构建供桌面与 Android 实机回归。真实 UI 的最终回归证据由总体验收报告补充。

## 兼容范围

协议名称与既有事件格式保持不变；新字段可选，旧快照保持可读。旧节点会忽略撤销凭证，因此完整撤销体验要求参与设备更新本轮版本。这个限制没有通过返回私人历史或信任未验证状态标记绕过。

## 隐藏群的活动选择修复

完整测试进一步发现：移除最后一个群后，前端选择空状态，但 Core 的 `activeGroupId` 仍指向已隐藏记录；重启可能再次打开该群。现在退出或移除当前群后会选下一个可见群或空，并保存到设置；启动和 bootstrap 过滤隐藏记录，直接 `select_group` 选择隐藏群也会拒绝。旧版本残留的设置会在启动时修复。

回归还验证：已撤销群移除后回落到另一个可见群，重启保留回落结果；移除最后一个群后活动群为空，重启仍为空，陈旧设置也不能复活隐藏群。上述变化未引入记录恢复或归档入口。

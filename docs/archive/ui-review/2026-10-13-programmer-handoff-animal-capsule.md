# 拾传 bug 修复与动物胶囊实现交接

请修复下述 5 个已确认问题，并把桌面贴边入口实现为用户选定的「动物胶囊」。目标是让文件只进入正确群组的待发草稿，发送过程中不丢附件，窗口收起与恢复稳定且不打断正在使用的应用。

基线为 2026 年 10 月 13 日当前工作区的 Tauri 0.6.0-alpha.1，包含现有未提交改动。开始前检查工作区状态，保留既有改动。沿用当前 Tauri 客户端及 Rust 核心。

## 修复任务

| 优先级 | 问题和触发条件 | 代码入口 | 修复要求 |
| --- | --- | --- | --- |
| P1 | 打开群 A、群 B 两个窗口，向 A 的动物入口拖文件，两个群都可能收到文件 | `apps/tauri/src-tauri/src/lib.rs` 的 `forward_anchor_drop`，`apps/tauri/src/main.js` 的 anchor-drop 处理器 | 窗口局部事件改为 `emit_to` 定向投递；监听限定当前窗口；payload 包含 owner label、groupId、dropId，校验归属并去重。groupId 固定为拖入时的目标。 |
| P1 | A 文件发送中选择 B，A 完成后 B 草稿被清除，但 B 没有发送 | `apps/tauri/src/main.js` 的 composer submit、`sendFiles`、`renderFileDrafts` 和文件选择器 | 每份附件建立稳定 draftId；本批次用快照；结束后只移除成功条目，保留失败与期间新增的条目。移除草稿不能修改正在遍历的发送数组。 |

Tauri 的 `window.emit()` 仍然是广播，不能因为调用对象是某个窗口就视为定向通知。先解决事件归属，再调整胶囊样式。

## 用户确定的设计

采用 **动物胶囊**。保留完整动物形象，并用有背景的容器明确表达可点击、可拖动和可接收文件的入口。实现稿：[动物胶囊交互参考](../ui-concepts/2026-10-13-animal-capsule/index.html)。它是交互示意，图中的文件、在线设备和数量均为演示内容，正式产品必须来自真实状态。

| 项目 | 实现约定 |
| --- | --- |
| 收起入口 | 64×64 逻辑像素容器，完整 48×48 动物；朝屏幕内部的一侧约 16px 圆角，贴边一侧平直；透明窗口容纳不透明胶囊，浅色/深色均可辨认。 |
| 位置 | 默认右侧，支持左侧，其他现有边缘能力保持可恢复；使用 OS 工作区，避免菜单栏、Dock、任务栏和屏幕外区域。 |
| 状态 | 未读/失败/待发使用真实数据和明确语义；无状态时不显示徽标，不把模拟稿中的数字 2 写入产品。群名可通过提示及右键菜单识别。 |
| 悬停预览 | 停留约 300ms 后展示最近文件；保留胶囊，预览面板与胶囊间隔约 12px，保持沿边方向的中心关联。预览不激活键盘窗口，不抢原应用焦点。 |
| 点击操作 | 点击胶囊、预览中的打开群组或恢复快捷键，展开并激活群窗口；此时隐藏胶囊。保留用户已保存的面板尺寸，默认 320×420，现有范围 300–380×360–520。正式面板靠工作区边缘，无 64px 动物占位偏移。 |
| 拖入文件 | 胶囊出现明显接收反馈；放下后展开目标群并展示待发草稿。放下即结束 hover 保护，待发附件仍可保留。整个流程不自动发送。 |
| 收起 | 临时预览离开「胶囊＋间隙＋面板」联合区域约 700ms 后收起，重新进入取消计时。主动操作时鼠标离开本身不收起；Esc 或失去焦点后依自动收起偏好处理。未发送内容始终保留。 |
| 置顶与自动收起 | 置顶只管理层级；自动收起是独立偏好。系统弹窗、应用弹层和拖动期间暂停收起，结束后重新判断。 |
| 多窗口 | 每个胶囊属于一个 owner，沿边排布避免覆盖，关闭/恢复/切群不改变其他 owner 的状态。 |

预览与主动操作需要不同的原生显示/激活路径。macOS 不能仅靠不调用 `set_focus()` 就假设 `show()` 不激活；应检查当前 Tao/Wry 行为并实测。键盘焦点在主窗口交互控件内时也要保护操作，不只保护消息输入框。

## 停靠与动效

拖动时显示停靠预览，松手再吸附；不在 native Moved 过程中反复设置窗口坐标。进入阈值先采用 24 逻辑像素，脱离阈值先采用 40 逻辑像素，避免边缘抖动；角落优先保留原停靠边。跨显示器按目标显示器比例换算，保持面板逻辑尺寸。

用约 180ms 的位移与淡入表现展开，收起约 150ms。动画可反向打断，并尊重 reduced-motion。 native 位置/大小变化与 UI 动画协调，避免出现透明大窗口挡住其他应用、丢失点击、先显示错误尺寸再纠正或胶囊与面板同时闪烁。示意稿的动画不是可直接复制的原生窗口实现。

## 必须通过的验收

### 文件与窗口隔离

1. 两个不同群窗口：向 A 胶囊拖文件，只有 A 增加一份草稿，B 没有草稿、消息或发送调用；点击 A 发送只传到 A。
2. 两个同群窗口：一次拖入只创建一次待发条目，一次点击发送只产生一次消息。重复 dropId 不重复入队。
3. 选择文件、主窗拖入、胶囊拖入都不立即发送；没有群或成员权限失效时保留未发内容并提示。
4. A 发送期间新增 B：A 完成后 B 仍可见，重启后 B 仍在；失败、取消、重试和切群同样不丢新草稿。
5. 发送多文件期间移除某条草稿，不让其他附件被跳过；已开始传输的项使用明确的传输取消流程。
6. A 贴左、B 贴右，分别置顶、缩放、切换动物，另一窗口的几何、按钮和动物均保持正确。
7. Enter→Drop、Enter→Leave、取消、无法读取的文件均释放对应保护；后续预览可正常收起。关闭一个弹层不清除仍在进行的拖动/系统对话框保护。

### 原生胶囊交互

1. 在其他应用输入时悬停胶囊，预览可见，输入仍进入原应用；点击胶囊后拾传获得键盘焦点。
2. 指针从胶囊经 12px 间隙进入预览，不闪烁或收起；快速移出再进入不会触发旧计时器。
3. 主动操作窗口用键盘选择文件/消息时，指针在窗口外也不误收起；系统文件对话框、应用弹层和原生拖出期间不误收起。
4. 胶囊与窗口实际手拖可跨边、脱离、重新停靠；几何吸附发生在松手时，恢复不改变保存尺寸，不出现动物宽度的正式面板偏移。
5. 最小/最大尺寸、浅色/深色、reduced-motion、连续展开收起、多 owner 胶囊碰撞均可用。工作区发生变化后恢复位置可见。
6. 单屏 macOS 真实手拖与焦点交接必须实测；多屏不同 DPI、屏幕负坐标、跨屏接缝和 Windows 用可用设备验证。缺少设备的项目明确列为未验收。
7. 原始群记录、真实文件、系统剪贴板和已有设备设置不用于破坏性测试；使用隔离节点与临时测试文件。

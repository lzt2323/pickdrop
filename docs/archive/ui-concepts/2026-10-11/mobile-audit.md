# PickDrop 手机 UI 审查与画板方案

审查时间：2026-10-11。范围：React Native 源码；未运行真机，因此布局风险不等同于已确认的渲染故障。使用 ui-ux-pro-max 的可访问性、触控、安全区、导航检查表，并查询 react-native 的 touch targets 指南。没有改动产品代码。

## 手机画板清单

建议 Paper 使用 390 × 844，主内容横向内边距 20。画板中至少完成前 8 个；状态以独立补充画板或元件状态板交付。

1. **群聊首页**：顶部拾传标识与加入；本机名/连接说明；群列表包含动物、群名、最近内容、时间、在线台数；三项底部导航。无群时用一个主要「加入群聊」和次级「创建群聊」。
2. **群聊详情**：返回、动物/群名、更多；一行在线人数；日期/消息/文件卡；文件主操作「保存」；底部附件、输入、发送。不要同时堆叠成员头像条、离线条、申请条、队列条挤空消息区域，非紧急状态收束为一个摘要入口。
3. **传输中心**：进行中/历史；群筛选；单项名称、群、大小、百分比、阶段；取消/重试；完成项显示真实保存目的地。不能暗示暂停/断点续传，代码当前未提供。
4. **加入群聊**：扫码和粘贴邀请；手动输入作为其他方式；清楚说明须得到成员允许。相机权限拒绝保留粘贴通路。
5. **创建群聊**：名称、动物选择、创建；键盘出现时主操作保持可见；不把“创建成功”与“邀请生成中”混在按钮文案里。
6. **邀请设备**：群信息、邀请码与真实过期状态、复制邀请信息、重新生成；地址和端口次级但可见。当前手机未生成二维码，若画 QR 应标明建议新增能力或先不画。
7. **成员与申请**：待批准申请先于成员；设备名、本机、在线/离线；邀请按钮；群设置进入独立页；退出/解散在下方独立危险区域。
8. **我的/设备设置**：设备名称、本地接收位置、存储占用、清理说明；保存名称与清理副本各自独立。
9. **外部分享确认**：文件/文字摘要、目标群单选、放入待发送；区分已入草稿与已发送。
10. **文件预览**：图像、原始文件名、保存/分享、关闭；不支持格式可保存原文件。
11. **状态板**：初始加载、无群、无历史、等待批准、邀请过期、连接中、离线可查看历史、传输失败重试、保存取消、原文件已清理、权限拒绝、草稿失去所属群后重新分配。

## 跨屏规范

- 360–430 宽：单栏；48 dp 主操作；底部导航 safe area；聊天输入有键盘状态稿。
- 600–839 宽：内容最大宽 600 居中，表单最大 480，不无限拉宽消息气泡。
- ≥840 宽：适配为群列表 + 当前群双栏；聊天与队列共享同一套状态含义。大屏不只是放大手机卡片。
- 1.5× 字号时允许按钮和状态换行，不把标题与固定控件争抢宽度；长文件名最多两行，可在详情查看全名。
- 浅色视觉建议：暖白背景、白表面、深灰绿正文、统一青绿色主操作；保留现有动物群标识，不将结构性图标换成 emoji。
